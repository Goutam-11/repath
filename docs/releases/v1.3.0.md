# repath v1.3.0

**2026-11-20 — the first tagged release.** One binary over SQLite that answers
structural questions about a codebase (*what breaks if I change this*, *how does
A reach B*, *where is the important code*) for humans and coding agents, with no
LLM, no daemon, and no network calls.

## Why v1.3.0 as the first tag

The codebase already shipped three named waves (v1.1 entrypoints/tests/check,
v1.2 compiler adapters/SARIF/serve/release plumbing, v1.3 LSP facts/xlang/trace)
and its contract (schema v6, 24 locked decisions) is documented in `PLAN.md`.
`v0.1.0` would name a surface the docs do not describe; v1.3.0 names the state
that is actually there. The project is still early — read the limitations below
before relying on a specific edge.

## What is in it

- **Languages**: TypeScript/JavaScript, Python, Rust. Imports, re-exports
  (including TypeScript barrels/workspaces/static dynamic imports and Python
  star re-exports), class bases, Rust module trees/`use`/generic bounds.
- **Six answers**: `find`, `callers`, `impact` (including `--diff` for a git
  change set), `path`, `map` (+ `--md` bundle), `flows`. Plus `tests`/`tests
  --diff`, `check` (+ `--sarif`), `trace`, `export --graphml|--dot`,
  `adapter --scip|--lsp-facts`, `install`/`uninstall` for agent skills.
- **Agent surfaces**: `repath mcp` (stdio JSON-RPC, legacy and 2026-07-28
  discovery eras), the embedded skill at `skills/repath/SKILL.md`, and the
  read-only `repath serve` (six answers over loopback HTTP).
- **Scale/caching**: incremental git-aware reindex, parallel git worktrees that
  warm from an immutable commit-keyed cache, packed references for bounded cold
  RSS, `index --scope` for monorepo subtrees, `index --artifact`/`pull`
  (uncompressed SQLite, opt-in zstd).
- **Evidence**: opt-in corpus matrix and compiler accuracy in
  `docs/benchmarks.md` (django 3,051 files, Kibana 38,548 files, requests,
  rayon), synthetic 10k/50k budgets, and the answer-token measurement (33x fewer
  tokens than reading the named files across the three corpora).

## Install

```sh
version=1.3.0
arch=amd64          # or arm64
base="https://github.com/Goutam-11/repath/releases/download/v${version}"
curl -LO "${base}/repath_${version}_linux_${arch}.tar.gz"
curl -LO "${base}/checksums.txt"
sha256sum --check --ignore-missing checksums.txt
tar -xzf "repath_${version}_linux_${arch}.tar.gz"
sudo install -m 0755 repath /usr/local/bin/repath
repath --version    # v1.3.0
```

The binaries are dynamically linked (cgo/tree-sitter): a minimal container needs
glibc and libgcc. There is no pure-Go build. From source: `make build` (Go 1.27+
and a C toolchain).

## Verify

```sh
cd /path/to/repo
repath status --json        # builds .repath/index.db on first use
repath impact <symbol>      # a structural answer
repath install --all        # copy the agent skill into agent config dirs
```

The release workflow builds both architectures with cgo, writes
`checksums.txt`, and attaches a source archive. This is the first tag, so the
reachability/accuracy tables in `docs/benchmarks.md` (pinned commits and
producer versions) are the reference numbers for this build.

## Known limitations (unchanged by the release)

- Parser gaps for some valid TypeScript (`call<typeof import("x")>()` is stored
  with `parse_ok=0` and partial symbols).
- Python imports search the repo root, `src/`, and `lib/` only; namespace
  packages without `__init__.py`, `sys.path`, and `__getattr__` re-exports stay
  unresolved (the last one is recovered at 0.60 only with import provenance).
- Rust macro bodies are blind; generic containers and `impl Trait` parameters
  are not inferred.
- No Go support yet ([#80](https://github.com/Goutam-11/repath/issues/80),
  decision-gated). `pnpm-workspace.yaml` workspaces are not read
  ([#79](https://github.com/Goutam-11/repath/issues/79)).
- `repath serve` is read-only, loopback by default, unauthenticated if widened;
  there is no UI, auth, config file, or seventh MCP tool.
- Cross-language HTTP links are literal-path only and opt-in at
  `--min-confidence 0.4`.
- A scoped index is per worktree; a fresh worktree/cache seed starts whole-repo
  until `index --scope` runs again.
